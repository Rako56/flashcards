<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer → GitHub Actions runner | Untrusted code runs in CI; secrets must be scoped to needed jobs only |
| GitHub branch protection → admin override | Even admins can bypass protection if "Allow administrators to bypass required pull requests" is on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1.5-01 | Tampering | Direct push to main bypasses CI | HIGH | mitigate | Branch protection: no direct pushes to main; PR required (Task 4 manual setup) |
| T-1.5-02 | Tampering | Admin bypasses branch protection | HIGH | mitigate | "Allow administrators to bypass required pull requests" set to OFF (Task 4) |
| T-1.5-03 | Information Disclosure | CI logs leak SUPABASE_SERVICE_ROLE_KEY | HIGH | mitigate | service_role NOT used in Phase 1 CI (only NEXT_PUBLIC_* + SUPABASE_ACCESS_TOKEN for CLI auth); GitHub auto-masks secrets in logs |
| T-1.5-04 | Tampering | Workflow file modified to skip gates | HIGH | mitigate | `.github/workflows/ci.yml` change requires PR; main branch protection ensures it goes through review |
| T-1.5-05 | Repudiation | Reviewer rubber-stamps PRs | LOW | mitigate | CODEOWNERS makes Rafael required reviewer on money paths; review history visible per-PR |
| T-1.5-06 | Spoofing | Forked PRs run CI with secrets exposed | MEDIUM | mitigate | GitHub default policy: secrets NOT exposed to forked PR workflows; verify Settings → Actions → "Send write tokens to workflows from pull requests" is OFF |
| T-1.5-SC | Tampering | GitHub Action versions pinned only to major | MEDIUM | accept | Use @v4 for major actions; Dependabot weekly updates (Task 2) catches CVEs; full SHA pinning is overkill for trusted vendors (Vercel, Supabase, GitHub) |
</threat_model>
