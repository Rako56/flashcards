<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon role → Postgres | Unauthenticated reads possible — RLS must enforce on every table |
| authenticated role → Postgres | Logged-in users — RLS must scope rows to their user_id |
| service_role → Postgres | Bypasses RLS by default; only used from `lib/supabase/admin.ts` with `'server-only'` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1.7-01 | Information Disclosure | Missing RLS on a table exposes rows | CRITICAL | mitigate | Every table includes `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` + ≥1 policy; Task 6 verifies via `pg_policies` query |
| T-1.7-02 | Information Disclosure | service_role + missing search_path = security risk | HIGH | mitigate | All functions use `SET search_path = public` (Supabase advisor warns otherwise) |
| T-1.7-03 | Tampering | Forward-reference policy (CREATE POLICY references future table) fails at apply | MEDIUM | mitigate | Defer admin-role policies to 0004 (after user_roles exists); only forward-reference is fn_user_has_access body which Postgres permits (not validated until call) |
| T-1.7-04 | Information Disclosure | CPF stored in plaintext | HIGH | accept | LGPD/CDC require CPF storage for refund/audit; access controlled by RLS + service_role; encryption at rest via pgcrypto deferred to P3 |
</threat_model>
