<objective>
Wire the types generation pipeline that locks Postgres schema ↔ TypeScript types together. After every migration: developer runs `pnpm types:gen` → commits the updated `types/database.types.ts`. CI catches stale types: if a PR adds a migration without regenerating types, the `types-fresh` job fails RED. Replace the Plan 1.6 stub `Database` with the real generated types so every Supabase client is fully typed.

Purpose: This is FOUND-12 — the gate that prevents the legacy class of bug "code references a column that doesn't exist" (RESEARCH.md Pitfall P5/P15). Migrations are the source of truth; types follow automatically; CI enforces freshness; pre-commit nudges. Combined with the lint rules in 1.2 banning `: any`, there's NO path to ship code referencing schema that doesn't exist.

Output: Real `types/database.types.ts` committed; CI types-fresh job ACTIVE on every PR; pre-commit reminder for migration changes; README documented.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migrations folder → types file | Every schema change must produce a type change; drift is a bug class |
| CI types-fresh job → main branch | Without CI gate, types can drift silently; legacy class TD-05 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1.9-01 | Tampering | Code references a column that doesn't exist | CRITICAL | mitigate | Generated types are the contract; tsc fails on stale types or schema drift; CI types-fresh job catches missing regen |
| T-1.9-02 | Tampering | Hand-edited types/database.types.ts diverges from schema | HIGH | mitigate | File has "DO NOT hand-edit" comment; CI regenerates and fails on diff |
| T-1.9-03 | Information Disclosure | Generated types expose private schema details to client bundle | LOW | accept | Types are compile-time only; never bundled to client (TS types erased) |
| T-1.9-04 | Tampering | `as any` cast around stale types | HIGH | mitigate | ESLint `no-explicit-any` blocks (Plan 1.2); developer MUST regen instead |
| T-1.9-05 | Spoofing | CI runs against wrong project (no link) | MEDIUM | mitigate | CI uses `SUPABASE_PROJECT_ID` + `SUPABASE_ACCESS_TOKEN` secrets; `supabase gen types --linked` resolves via these |
</threat_model>
