## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sentry → external service | Errors include payload data; PII must be scrubbed before sending |
| pino logs → Vercel logs ingestion → 3rd party analysis | Logs persist; redact paths protect from PII leakage |
| middleware → all routes | Every request flows through middleware; correlationId propagation must not break |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1.10-01 | Information Disclosure | Sentry breadcrumb leaks CPF/email | CRITICAL | mitigate | `beforeSend` scrubs `event.user.email + .cpf`; CPF regex scrub in messages; cookie/authorization headers deleted |
| T-1.10-02 | Information Disclosure | pino logs leak PII to stdout | CRITICAL | mitigate | `redact.paths` covers cpf/password/token/email/refresh_token/authorization/cookie; `censor: '[REDACTED]'` |
| T-1.10-03 | Tampering | Middleware misconfigured causes 500 on every request | HIGH | mitigate | P1.10 middleware is passthrough (no logic to break); P2 adds subdomain logic carefully |
| T-1.10-04 | Spoofing | Untrusted client provides x-correlation-id | LOW | mitigate | correlationId is for tracing only, not security-sensitive; if attacker provides their own UUID, we log under that ID — no privilege escalation |
| T-1.10-05 | Denial of Service | pino transport in middleware causes runtime mismatch | HIGH | mitigate | pino is Node-ONLY — never imported in middleware.ts (which is runtime: 'nodejs' in 15.5 but historically edge). Middleware uses `crypto.randomUUID()` from Web Crypto, not pino. RESEARCH.md Pitfall P18. |
| T-1.10-SC | Tampering | New npm packages (sentry, pino, pino-pretty) | LOW | mitigate | All [VERIFIED: official Sentry + pino] per RESEARCH.md Audit |
</threat_model>

    import { NextResponse, type NextRequest } from 'next/server'

    export function middleware(request: NextRequest): NextResponse {
      const correlationId = request.headers.get('x-correlation-id') ?? crypto.randomUUID()
      const requestHeaders = new Headers(request.headers)
      requestHeaders.set('x-correlation-id', correlationId)

      const response = NextResponse.next({ request: { headers: requestHeaders } })
      response.headers.set('x-correlation-id', correlationId)
      return response
    }

    export const config = {
